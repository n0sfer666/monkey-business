# ui-diff — сверка стенда с макетом (А.2)

Рендерит борд макета и экран стенда на одной ширине в одном движке, сопоставляет элементы, меряет computed styles и делает pixel diff. Отчёт — сырьё для аудита по формату Е.2. Вердикт выносит человек, а не инструмент.

## Запуск

Нужны стенд (`make dev FIXTURE=1`, localhost:8090) и глобальный Playwright с браузерами chromium и webkit.

```nu
make ui-diff SCREEN=servers WIDTH=1280
```

Без `SCREEN`/`WIDTH` прогоняются все записи `boards.js`. Флаги CLI: `--screen --width --theme dark,light --engine chromium,webkit --boards <dir> --out <dir>`. Окружение: `MB_UI_BASE`, `MB_UI_PASSWORD`, `MB_VM_SUB_FILE` (файл подписки, как у `make dev`). Без URL подписки прогон не стартует: скрабить нечего.

Отчёт пишется в `.context/investigations/ui-diff/<YYYY-MM-DD-HHMMSS>/` (gitignored):
- `index.md` — сводка прогона;
- `<Board>-<width>-<theme>-<engine>.md` — отчёт;
- `.json` — сырые замеры;
- `.board.png` (один на борд × движок), `.impl.png`, `.diff.png` — снимки, diff с пронумерованными регионами.

## Борды

Борды лежат в `.context/investigations/ui-diff/boards/` и не коммитятся. Обновляются из артефакта макета через Artifact `read` с `paths` и `out_dir` = эта папка:
- `artifact-type/dc-runtime.js` — в HTML подключается как `./support.js`;
- `project/<Board>.dc.html` — для каждого борда из `boards.js` и модалок.

Новый экран или состояние (например, борд с `props`) — новая строка в `boards.js`. Состояние, которое держит логика борда, а не props, задаётся кликами: `boardClick` и `standClick` — CSS-селекторы, по которым кликнуть перед замером, `state` — суффикс имени отчёта (`MobileServers-list`, `MobileServers-arrange`).

Состояние стенда, которое не задать кликом (нет geo-файла, подписка без лимита), ставят ssh-хуки `setup` / `teardown` записи (`vm.js`): `setup` перед замером, `teardown` всегда после, даже если замер упал. Хуки меняют VM: прячут `/usr/share/xray/geosite.dat` в `.uidiff` и снимают `total` у подписок, сохранив `/etc/config/monkey-business` в `/tmp/mb-uidiff.conf`. После прогона этих файлов быть не должно. Нужен `sshpass`. Хост — `MB_VM_SSH_HOST` / `MB_VM_SSH_PORT` / `MB_VM_SSH_PASS` (по умолчанию `root@localhost`, 2222, `root`). На хост не из localhost хуки не идут без `MB_UI_DIFF_REMOTE_HOOKS=1`, чтобы не тронуть роутер.

## Что считается

1. **Кадр.** У борда — корень дизайна, у стенда — `#view`. Шапка LuCI отрезана, кадры совмещены по левому верхнему углу.
2. **Матчинг.** Сначала точное совпадение текста (собственный текст, aria-label, placeholder, label; `[PLACEHOLDER]` борда = любое слово) и роли. Затем ближайший сосед той же роли внутри сопоставленного контейнера: по отступу от левого или правого края и от верха, в пределах 64px; из кандидатов берётся тот, у кого меньше сумма отступа и половины разницы размеров. Ключ из одних плейсхолдеров в первом проходе не участвует. Что не сопоставилось — «нет» или «лишнее» (major).
3. **Стиль** (minor). Точно: кегль, вес, mono/sans. С допуском ±2px: высота, ширина контролов, радиус, рамка, паддинги, положение по x от краёв контейнера. Цвета — только в тёмной теме.
4. **Тексты.** Различие статичного текста борда — «тексты» (minor). Различие привязанного (`{{…}}`) — «данные», их разбирает человек.
5. **Pixel diff** — только в тёмной теме: YIQ-порог 0.1, клетки 8×8, регионы от 16px, плюс diff каждой сопоставленной пары. В светлой теме — контраст ≥ 4.5 (≥ 3 для 24px+ или жирного от 18.66px).
6. **Console/network** — с успешной загрузки экрана. Console error — blocker.

URL подписки, хост и ссылки серверов вычищаются из текстов отчёта (`<SUB_URL:n>`, `<HOST:n>:port`, `<LINK:n>`) и закрашиваются на снимке стенда. Если страница перерисовала их во время снимка, снимок переснимается, а после трёх неудач прогон падает.
