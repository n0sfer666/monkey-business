# Корпоративные маршруты и доступность VPN

Корпоративные шлюзы настраиваются в **Dashboard → Routing → Corporate tunnels**.
Укажите публичный IPv4 шлюза и, при необходимости, порт TCP/UDP. У каждого правила
есть переключатель **Via VPN** и флаг **Tunnel requires UDP**. Разрешено до 32 правил.
Точный порт имеет приоритет над правилом без порта для того же адреса. Выключенное
правило явно отправляет трафик напрямую. Переопределение действует на LAN, включая
порт 53; диагностика и bootstrap роутера используют отдельные пути.

Редактирование, удаление и Undo меняют черновик страницы. **Save & Apply** применяет
только режим, регион, custom-списки и корпоративные правила. Фактически работающие
сервер, credentials, DNS и остальные настройки сохраняются. Во время Apply затронутые corporate proxy-потоки кратко блокируются до согласованности движков и сохранённого состояния; посторонний трафик и точные direct-исключения сохраняют свою область. При отказе черновик
остаётся, ошибка отображается. Потерянный ответ можно повторить с прежним request ID.
**Discard changes** восстанавливает последнее полученное сохранённое состояние.
При уходе с несохранённым черновиком предлагается остаться либо отбросить изменения.

После загрузки, явного включения VPN и смены outbound включённые corporate rules
начинают с direct. Два успешных раунда здоровья разрешают VPN. Два провала HTTPS
включают direct-fallback; два провала UDP делают это только для правил, требующих
UDP. Внутренняя ошибка диагностики означает unknown и сохраняет действующий маршрут.
HTTPS и UDP независимы. Автоматическое возвращение через VPN учитывает cooldown
60 секунд и сбрасывает только соответствующие исходные LAN-соединения; ошибка
точного сброса отображается отдельно. При выключенном VPN монитор не отправляет пробы.

**Check availability** запускает на роутере задание для узла, подписки либо всех
узлов, включая выключенные, — до 200 за задание. Закрытие окна прогресса не отменяет
его; для этого есть **Cancel check**. HTTPS-статус, базовые задержка/доля успехов,
UDP и возраст измерения показываются отдельно. Провал означает недоступность
диагностических целей, а не доказанную неработоспособность всех приложений или
корпоративных VPN.

Две HTTPS-цели проверяются параллельно: проверка TLS, без редиректов, ожидаемый
HTTP-статус 200/204, ответ до 4096 байт. UDP проверяется через два STUN-сервера.
Пять лучших HTTPS-кандидатов получают дополнительный запрос. Задержка и доля
успехов считаются только по базовым пробам. Результат устаревает через пять минут
либо при смене узла, метода, загрузки или известного поколения сети. Здоровье
активного VPN показывается отдельно от ручного рейтинга. До 500 результатов хранятся
в tmpfs до 10 минут независимо от четырёх историй jobs. Отмена незавершённой
дополнительной пробы сохраняет прошлый завершённый результат и исходное время базы.

**Sort** меняет черновик внутри исходных позиций групп подписок/ручных узлов;
выключенные и ручные узлы и активная подписка сохраняются. **Apply priority** сохраняет
только приоритеты и не переподключает VPN. **Save** в редакторе узла помещает его
поля в staging LuCI; обычные изменения редактора/настроек применяются через Apply
конфигурации LuCI и могут переподключать VPN. Connect подтверждает выбранный узел
через VPN до изменения работающего outbound; неподтверждённый fallback не выбирается.

HTTPS-цели редактируются отдельно в **Settings** и имеют собственное scoped Apply.
Read-only пользователь видит безопасные статусы и результаты, но не может запускать
или отменять проверки, читать полную UCI, загружать geo-файлы и менять настройки.

## Совместимость и переход

Нужны cgroup v2 с `cgroup.kill`, nft socket-cgroup (`kmod-nft-socket`), TPROXY,
модули ucode fs/uci/socket, `curl` с CA-сертификатами, GNU `timeout`, `flock` и
`conntrack`. При отсутствии обязательной изоляции запуск явно отказывает.
Квалифицированные локальные версии и аппаратные ограничения указаны в
[приёмочном документе](routing-availability-acceptance.md).

Сервис procd `monkey-business-observer` содержит jobs, единственный observer
с интервалом 15 секунд и recovery. Установка удаляет прежнюю cron-строку watchdog;
старый watchdog теперь только проверяет статус для совместимости. После обновления
перезагрузите страницу LuCI: старые ping RPC возвращают API v2 `deprecated`.
Новые RPC используют typed refs, асинхронные jobs и отдельные revisioned Apply
для routing/order/settings. Доступ read-only к UCI удалён; редактор доступен writer.
До явного действия существующие маршруты и приоритеты сохраняются. Если старая установка не имеет applied snapshot, явный Connect/enable создаст подтверждённый снимок; routing-only Apply не угадывает его по изменяемой подписке.

Подписки и загрузки требуют HTTPS с проверкой сертификата. Raw-подписки сохраняются
приватно и должны быть очищены от credentials перед использованием в тестах.
Корпоративные проверки и установка на реальный роутер требуют отдельного разрешения.
