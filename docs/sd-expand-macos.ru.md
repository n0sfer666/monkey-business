# Расширение ext4-раздела SD-карты с macOS

[English](sd-expand-macos.md) | **Русский**

Штатный образ ImmortalWrt для NanoPi R2S оставляет rootfs в пару сотен МБ независимо от того,
насколько велика ваша SD-карта. Добавьте xray-core (~25 МБ) и два geo-файла `.dat` (~30 МБ) — и
overlay забит под завязку, а `apk` начинает падать с «no space left on device».

Обычно это лечат расширением раздела на Linux-машине. `scripts/expand-sd.sh` делает то же самое
**нативно на macOS**: системными `diskutil`/`fdisk`/`gpt` плюс `e2fsprogs` из Homebrew. Без
Linux-VM и без Docker.

> Так можно растянуть только **ext2/3/4**. Если overlay в вашем образе — **f2fs**, скрипт не
> поможет: под macOS нет инструмента resize для f2fs.

---

## Перед началом

1. **Сделайте бэкап карты.** Скрипт правит таблицу разделов. Он не запустится без явного
   подтверждения, но бэкап за вас **не делает**. Полный образ (`dd if=/dev/rdiskN of=…`) или хотя бы
   первый МБ — дешёвая страховка.
2. **Поставьте e2fsprogs** — формула keg-only, в `PATH` ничего не кладётся; скрипт сам ищет её в
   префиксах Homebrew:
   ```sh
   brew install e2fsprogs
   ```
   Скрипт **ничего не устанавливает** — только проверяет и сообщает, чего не хватает.
3. **Выключите роутер, достаньте карту, вставьте в Мак** и найдите её устройство:
   ```sh
   diskutil list
   ```
   Нужно устройство целиком (`/dev/disk14`), а **не** раздел (`/dev/disk14s2`). Внимательно читайте
   строки `Removable Media` / `Media Name`: указать внутренний диск — единственная ошибка, от которой
   скрипт вас не защитит.

---

## Запуск

```sh
sh scripts/expand-sd.sh /dev/disk14
```

Скрипт печатает план и просит ввести имя раздела (`disk14s2`) для подтверждения. Любой другой ввод —
выход. Нужен `sudo` (raw-чтение, правка таблицы, операции с ФС), пароль будет запрошен.

Что происходит по шагам:

1. Определяется схема (MBR или GPT) и выбирается **самый большой раздел** — это и есть
   rootfs/overlay.
2. Проверяется, что на старте раздела действительно лежит **первичный** ext-суперблок: сверяется
   магия `0xEF53` **и** `s_block_group_nr == 0`, поэтому резервная копия суперблока скрипт не
   обманет. Если старт в таблице не совпадает с реальным положением ФС, скрипт сканирует карту
   (шагом 1 МБ), находит настоящий старт и чинит таблицу — сбитый offset обычно и есть причина, по
   которой карта «не монтируется» после неудачного ресайза где-то ещё.
3. Размонтирует диск, растягивает раздел до конца карты, затем гоняет `e2fsck -fy` и `resize2fs`.
   Обратите внимание на `-y`: починка применяется без вопросов.
4. Проверяет через `dumpe2fs`, что ФС теперь занимает весь раздел.

### Может попросить извлечь карту и запустить ещё раз — это нормально

macOS кэширует таблицу разделов. Если ядро не перечитало её после правки, скрипт корректно
останавливается и пишет:

```
>> ИЗВЛЕКИ И ВСТАВЬ карту, затем запусти скрипт снова — он доделает только ФС.
```

Извлеките (`sudo diskutil eject /dev/disk14`), физически вставьте карту заново и повторите ту же
команду. Второй проход увидит исправленную таблицу и доделает только часть с ФС. То же самое, если
финальная проверка сообщит, что ФС не заняла весь раздел.

### Переменные окружения

| Переменная | Дефолт | Когда нужна |
|------------|--------|-------------|
| `MB_START` | — | Задать старт раздела вручную (в секторах). Нужна, если скан не нашёл первичный суперблок, а вы знаете, где он. Скрипт всё равно проверит, что суперблок там первичный, и откажется, если нет. |
| `MB_SCAN_MB` | `512` | Насколько глубоко (в МБ) сканировать карту в поисках суперблока. Увеличьте, если скан ничего не нашёл. |

```sh
MB_START=131072 sh scripts/expand-sd.sh /dev/disk14
MB_SCAN_MB=1024 sh scripts/expand-sd.sh /dev/disk14
```

```nu
# nushell
with-env { MB_START: "131072" } { sh scripts/expand-sd.sh /dev/disk14 }
with-env { MB_SCAN_MB: "1024" } { sh scripts/expand-sd.sh /dev/disk14 }
```

## После

Верните карту в R2S, загрузитесь и убедитесь, что место появилось:

```sh
# df -h /            # rootfs должен соответствовать размеру карты
# df -h /overlay
```

Дальше — по [руководству по установке](install-nanopi.ru.md), либо просто перезапустите
`make deploy`: теперь он сможет доставить xray-core и geo-базы.

---

## Известные ограничения

- **Целевой раздел выбирается автоматически** (самый большой). Указать другой нельзя.
- **Нет ни dry-run, ни `--yes`.** Ввод подтверждения — единственный барьер, и он же единственное, что
  стоит между опечаткой в имени устройства и внутренним диском с ext-разделом.
- **Резервный суперблок никогда не принимается за первичный**, но и починить ФС, повреждённую
  сильнее, чем вытягивает `e2fsck -fy`, скрипт не сможет.
