# 2026-08-07 — Локальные проверки не должны требовать сеть

## Контекст
`make deploy HOST=root@192.168.1.1` падал ещё до заливки:

```
>> локальные проверки перед заливкой…
ERROR: failed to solve: alpine:edge: failed to resolve source metadata for
docker.io/library/alpine:edge: … Head "https://registry-1.docker.io/v2/library/alpine/manifests/edge":
net/http: TLS handshake timeout
make[1]: *** [test-build] Error 1
```

Случай не первый. Механика: `check`/`lint`/`test-unit` зависели от цели `test-build`, а та безусловно
звала `docker build -f Dockerfile.test`. Тег в `FROM alpine:edge` плавающий, поэтому BuildKit на
каждый вызов резолвит манифест в registry — даже когда собранный образ лежит на диске и меняться
ему незачем. Итог: любой перебой с Docker Hub (а он в РФ ломается регулярно) означал не «проверки
не прошли», а «проверить нечем, деплой на роутер отменён». При этом сами проверки сетью не
пользуются вовсе — контейнер только гоняет shellcheck/ucode/node по локальным файлам.

## Решение
**Образ — кеш, а не шаг сборки** (`scripts/docker-image.sh`, зовётся из Makefile):
- образ есть и `Dockerfile.*` не новее последней успешной сборки (штамп `.make/<image>.stamp`) —
  docker не трогаем вообще; побочный выигрыш — `make check` 0.3 с вместо 7 с;
- образа нет или Dockerfile правился — собираем;
- сборка не прошла, но образ на диске есть — предупреждаем и **работаем на нём**: устаревший на
  пару версий alpine ловит те же ошибки shellcheck/ucode, а несобираемость — не причина не пускать
  проверенный код на устройство;
- образа нет и собрать нечем — только тогда отказ, с явной подсказкой (`MB_SKIP_CHECKS=1`).

Штамп, а не `docker inspect .Created`: сравнивать RFC3339 в POSIX sh нечем, `find -newer` есть
везде. `.make/` в `.gitignore`, `make clean` его сносит.

**Обновление образа стало отдельной явной целью.** `make test-build` теперь принудительно
пересобирает (`MB_REBUILD_IMAGE=1`) и падает при ошибке — это единственная цель, которой нужна
сеть; тихо продолжать на старом образе там нельзя, о том и просили. Проверки ходят через
внутреннюю `test-image`. `test-integ` использует ту же обёртку.

**Запасные выходы у деплоя остались прежними** (`scripts/deploy.sh`): `MB_SKIP_CHECKS=1` — залить
без проверок, `MB_CHECK_CMD=…` — подменить набор.

## Правило
Всё, что запускается перед коммитом или деплоем, обязано работать без интернета, если по сути
своей сеть ему не нужна. Внешняя недоступность может замедлить проверку или сделать её чуть менее
свежей, но не имеет права её отменять. Плавающие теги (`edge`, `latest`) в путях проверок — только
за кешем, который умеет обходиться тем, что уже скачано.

## Проверка
T2, вручную с подменённым `docker` в PATH: сборка падает + образ есть → rc=0 и предупреждение;
сборка падает + образа нет → rc=1 и подсказка; `MB_REBUILD_IMAGE=1` + падение → rc=1. На живом
docker: `make lint` собирает и ставит штамп, повторный `make check` не обращается к docker вовсе.
