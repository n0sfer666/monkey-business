# 2026-07-26 — Своп nft-таблицы одной транзакцией

## Контекст
`scripts/firewall/apply.sh` менял таблицу двумя процессами: сначала `nft delete table inet
monkey_business`, потом отдельный `nft -f -` создавал её заново. Между вызовами в ядре нет ни
kill-switch (forward-drop), ни tproxy-перехвата: форвард LAN→WAN в это окно уходит открытым через
fw4 — то есть мимо туннеля, с настоящим IP клиента. Окно открывалось на КАЖДОМ применении: reload из
UI, `vpn_start`, и особенно фаза `down` watchdog'а (раз в минуту, до 144 раз в сутки).

Замер на железе (throwaway-таблица `mb_probe`, сэмплер в цикле параллельно пересозданию): старая
идиома — **80 отсутствий таблицы на 193 пробы**; окно не теоретическое.

## Решение
Один документ `nft -f`, три инструкции подряд:

```
table inet monkey_business          # add, идемпотентно: delete требует существования
delete table inet monkey_business
table inet monkey_business { … }
```

nft применяет файл целиком либо не применяет вовсе — промежуточного состояния «таблицы нет» не
существует. Отвергнутый документ оставляет прежний ruleset нетронутым (проверено `nft -c -f -` до
установки на живой роутер). Версия nft на устройстве — 1.1.6.

Замер после фикса: **0 отсутствий на 206 проб** на пробной таблице и 0 на боевом firewall за 10
переприменений подряд (pid xray не менялся, RU-сет оставался заполненным, 4880 элементов).

## Что осталось вне транзакции — намеренно
Элементы RU-сетов (`ru4.nft`/`ru6.nft`, ~4880 строк) грузятся отдельными `nft -f` ПОСЛЕ свопа и не
фатальны (`|| true`). Инлайнить их в тот же документ нельзя: битый или обрезанный файл сетов уронил
бы документ целиком, а на загрузке (прежней таблицы ещё нет) это firewall без kill-switch — LAN
светит в открытую сеть. Худший случай при текущей схеме — пустой bypass: RU-трафик идёт через
туннель, но правила на месте.

Поэтому гарантия атомарности в тесте названа честно — `atomic.swap_one_call` (своп таблицы), а не
«один вызов nft вообще»; загрузка сетов пинится отдельным блоком `ruset.*`.

## Тест
`test/unit/firewall_test.sh` (стаб nft логирует argv каждого вызова): своп — ровно один вызов
`nft -f -`; `delete table` не встречается отдельной командой; внутри документа порядок
add → delete → create. Отдельный блок с непустым `MB_RUSET_DIR`: 3 вызова, первый — своп, дальше
ru4/ru6. Негативные прогоны: возврат старой идиомы, потеря загрузчика ru6 и инлайн сетов роняют
ровно свои ассерты.
