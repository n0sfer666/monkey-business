## Требования

### F1 — Независимое ревью + фиксы
- Ревью свежим взглядом по группам модулей (независимые субагенты-ревьюеры, чтобы взгляд был
  действительно непредвзятым):
  - backend-логика: `src/parser/subscription.uc`, `src/lib/uri.uc`, `src/generator/xray.uc`,
    `src/rpcd/handlers.uc`;
  - рантайм/device: `root/usr/share/rpcd/ucode/monkey-business.uc`, `root/etc/init.d/monkey-business`,
    `root/usr/share/monkey-business/geo.sh`, `scripts/firewall/*.sh`, `root/etc/config/monkey-business`;
  - frontend: `luci/.../dashboard.js`, `servers.js`, `settings.js`, `menu.d`, `acl.d`;
  - dev/build/test: `Makefile`, `scripts/*.sh`, `Dockerfile.*`, `test/*`.
- Критерии: реальные баги, безопасность (shell-инъекции, экранирование, секреты в логах/tmp),
  POSIX-sh/shellcheck, ucode-идиомы (см. `conventions.md`), DRY/KISS/SOLID, файлы >200 строк,
  мёртвый код, нарушения конвенций, регрессии относительно прошлых фиксов.
- **Чинить ВСЁ реальное** (баги/безопасность/корректность) под `make test`. Спорное, рисковое
  (рефактор UI, ломающий контракт без нужды), косметику без выгоды — выносить в отчёт с severity.
- Не плодить ложные находки: каждую правку обосновать; не трогать gotcha-комментарии, документирующие
  реальные грабли.

### F2 — RU-версии документации
- `README.ru.md` — полный перевод `README.md` (структура 1:1: описание → Install → Development →
  Troubleshooting → Feedback → License).
- `docs/install-nanopi.ru.md` — полный перевод `docs/install-nanopi.md`.
- Кросс-линки: вверху EN-версий — ссылка на RU (`Русская версия`), вверху RU-версий — ссылка на EN.
- EN остаются основными (canonical). Внутренние ссылки в RU ведут на RU-аналоги
  (README.ru → install-nanopi.ru), внешние URL/якоря — без изменений.

### F3 — nushell-строки
- Во всех местах с **хост-командами** (исполняются на машине пользователя), где nushell-синтаксис
  отличается от POSIX sh, добавить вторую строку/блок с пометкой nushell.
- Отличаются прежде всего **env-var префиксы**:
  - `MB_VM_SSH_HOST=… MB_VM_SSH_PORT=… MB_VM_SSH_PASS=… sh scripts/deploy-vm.sh`
    → nushell: `with-env { MB_VM_SSH_HOST: …, … } { sh scripts/deploy-vm.sh }`.
  - `export MB_SDK_DIR=/path; make package` → nushell: `$env.MB_SDK_DIR = "/path"; make package`.
  - `MB_VM_HTTP_PORT=NNNN make dev-up` → nushell: `MB_VM_HTTP_PORT=NNNN make dev-up`
    (в nushell допустим `with-env`; уточнить идиому ниже).
- **НЕ трогать** команды, исполняемые на роутере (busybox sh): всё под `# …` / через `ssh` / `apk` /
  `nft` / `ubus` / `logread` — они в RU/EN остаются как есть.
- Команды без отличий (`make test`, `make dev-up`, `ssh root@…`, `brew install qemu`) — nushell-строку
  НЕ добавлять (KISS, нет дублирования впустую).
- Добавлять в EN и RU единообразно.

## Edge cases / нюансы
- nushell не наследует `export VAR=…; cmd` в одной строке так же, как sh; корректная идиома —
  `$env.VAR = "…"` (для сессии) или `with-env { VAR: "…" } { cmd }` (точечно). Для многострочных
  env-префиксов deploy-vm.sh использовать `with-env { … } { … }`.
- В nushell `=` в `FOO=bar cmd` как префикс **не** поддерживается напрямую → всегда `with-env`/`$env`.
- Markdown-блоки: nushell-вариант давать отдельным fenced-блоком (```nu) сразу после sh-блока,
  с короткой подписью «nushell:» — без переписывания sh-варианта.
- Кросс-линки не должны ломать существующие относительные ссылки (`docs/install-nanopi.md`,
  `../README.md`).
- Ревью не должно регрессить прошлые фиксы (golden-снапшоты region=ru пинят генератор).

## Риски и митигации
| Риск | Митигация |
|------|-----------|
| Ревью даёт ложные находки → лишние правки/регрессии | независимые ревьюеры + перепроверка каждой находки перед фиксом; каждый фикс под `make test` |
| «Чинить всё» ломает контракт | golden-снапшоты + unit/integ; рисковое выносить в отчёт, не править вслепую |
| Неверная nushell-идиома (env-prefix) | использовать `with-env`/`$env.X`, не `X=…` префикс; сверить с конвенцией пользователя (Nushell) |
| RU-перевод расходится с EN при будущих правках | EN canonical, RU помечен как перевод + кросс-линк; синхронность фиксируется в этом прогоне |
| Дублирование nushell там, где нет разницы | добавлять nushell только при реальном отличии синтаксиса |

## Тестовая стратегия
- **F1 (T1/T2, где затронут код — T4):** после каждого фикса `make lint && make check && make test-unit`
  зелёный; где затронут генератор/парсер/firewall — golden-снапшоты сверены, при возможности `make test-integ`.
  Новые баги в логике → регрессионный unit-тест (T4).
- **F2/F3 (T1):** вычитка; проверка, что все команды соответствуют Makefile/скриптам; nushell-строки
  синтаксически корректны (сверка идиом env/with-env); кросс-линки и относительные пути валидны.
- T3 (dev-VM/железо) — blocked в прогоне (нет запущенной VM/R2S); сетевые проверки — через netns-integ.
