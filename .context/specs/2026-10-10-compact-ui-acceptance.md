# Компактный UI — критерии готовности

Статус: согласовано с пользователем 2026-10-10 (интервью). Применяется к каждой итерации
компактного UI и к аудиту реализации. Поведение — `2026-10-10-compact-ui.md` и runbook
`2026-10-10-compact-ui-runbook.md`; вид — макет https://claude.ai/artifact/Qi9eCMkVJJSUMzKcLT3TFF
(версия 30, артефакт типа Design, борды в `project/*.dc.html`).

## Порог «готово»
Экран готов, когда по нему **ноль расхождений** любой severity: обе графы отчёта (поведение и
макет) — pass на 1280 и 390, в тёмной и светлой теме, в Chromium и WebKit. «Не проверено» без
согласия пользователя — не pass. Severity нужна для приоритета в спеках исправлений, не для допуска.

## А. Визуальное соответствие макету
1. Каждый борд из перечня, в каждом состоянии из столбца «Состояния», сверяется с реализацией на
   той же ширине (1280 для десктопа, 390 для мобилки). Состояние воспроизводится в VM; если
   воспроизвести нельзя — «не проверено» с причиной.
2. Метод: скриншоты борда и реализации бок о бок + замер `getComputedStyle` / `getBoundingClientRect`
   у соответствующих элементов.
3. Допуски:
   - отступы, размеры, радиусы — ±2px;
   - кегль и начертание (`font-size`, `font-weight`) — точно; семейство — системный sans / mono, как
     в борде;
   - цвет (тёмная тема) — hex совпадает с цветом борда;
   - тексты — дословно (подписи, кнопки, подсказки, плейсхолдеры, aria-label); отличаться могут только
     данные (`[N]`, `[DATE]`, `[SIZE]`, имена серверов и подписок);
   - иконки — та же форма и размер ±2px; нет лишних и недостающих.
4. Структура: те же блоки, контролы и порядок, что в борде. Лишний или недостающий блок или контрол —
   расхождение.
5. Светлая тема: отдельных бордов нет. Раскладка, размеры, тексты и иконки — как в тёмном борде;
   цвета — из светлых токенов `kit/tokens.js` (соответствие роли токена тёмному цвету борда);
   контраст текста ≥ 4.5:1 (≥ 3:1 для 24px+).
6. Хром LuCI: шапку ImmortalWrt (бренд, меню, Logout) не сверяю — это тема. Вкладки
   Dashboard / Servers / Settings сверяю с бордом: десктоп — подчёркивание активной, мобилка —
   сегменты на всю ширину, активная подсвечена.
7. Конфликт спеки и макета (пример: в бордах Servers/Settings есть h1 с подзаголовком, в спеке «h1
   нет», решено в пользу макета 2026-10-10): правда — макет. Конфликт идёт отдельной графой «конфликт спеки и макета» на решение
   пользователя и не считается дефектом реализации, пока решения нет.

## Б. Оверлеи: модалки, шторки, подтверждения, ⋮-меню, прогресс
Для каждого оверлея:
1. Открывается своим триггером — мышью/тапом и с клавиатуры (Enter / Space).
2. Закрывается по ×, Cancel, Esc и клику по подложке; в busy-состоянии (Fetching…, прогресс) Esc и
   подложка не закрывают.
3. При открытии фокус внутри (первое поле или первый пункт), Tab не уходит наружу; при закрытии
   фокус возвращается на триггер (или на заданный runbook элемент). Исключение — ⋮-меню (`role=menu`):
   Tab закрывает меню по ARIA-практике, фокус возвращается на ⋮ (решение 2026-10-10).
4. Страница под оверлеем не скроллится.
5. Вид сверен с бордом по разделу А (мобилка — нижняя шторка, кнопки стопкой, где так в борде).

## В. Функционал
1. Все шаги runbook итераций 1–3 на десктопе и мобилке.
2. Dashboard: каждый контрол и состояние бордов `Main` / `MobileDashboard` и модалок Routing / Geo —
   требование итерации 4 по спеке (статус, подписка, Exit IP / Check, трафик Hide/Show, Turn on/off,
   блок «geo data is missing», список серверов с Ping all / Sort / Connect, Routing Mode / Region,
   чипы, Custom rules Edit, Save & Apply, geo data Update…, hysteria2 Update). Пока итерация 4 не
   сделана — каждое отсутствие — расхождение.

## Г. Ошибки
1. Console: ни одного `console.error`, uncaught exception, unhandledrejection от приложения.
2. Network: нет 4xx/5xx и сбоев на запросах LuCI / ubus / статики.
3. UI: нет красных плашек и уведомлений об ошибках.
4. Допустимо: ошибки подключения и пинга VPN-серверов. Сброс slirp-проброса QEMU
   (`ERR_CONNECTION_RESET`, `L is not defined` при загрузке) — допустим, только если после повторной
   загрузки страница работает; не лечится повтором — дефект.

## Д. Ширины, браузеры, навигация
1. Сверка с макетом и полный прогон — 1280 и 390.
2. 1440 / 1100 / 800 / 722 / 720 / 360 — целостность: нет горизонтального скролла, обрезания и
   наездов; строки не переносятся там, где не должны; по 720/722 включается нужная сторона
   брейкпоинта.
3. Браузеры: Chromium (десктоп + эмуляция телефона 390, touch) и WebKit (десктоп + iPhone 390).
4. Навигация на 390: матрица переходов — с каждой вкладки на каждую (6 переходов) и через вкладки, и
   через ☰-меню LuCI; страница отрисовала свой контент, активная вкладка подсвечена; прямая ссылка и
   перезагрузка на каждой вкладке; кнопка «назад» браузера.

## Е. Формат отчёта
1. По каждому экрану и борду — две графы: «поведение проверено» и «макет сверен», значения
   pass / fail / не проверено (+ причина). Третья графа — конфликты спеки и макета.
2. Расхождение: экран / борд / ширина / тема / браузер / ожидалось / есть / severity / скриншот.
3. Severity — по влиянию на пользователя:
   - **blocker** — экран или функция недоступны, потеря данных, ошибка приложения в console;
   - **major** — не по макету структурно (нет блока или контрола, лишний, другая раскладка), сломаны
     фокус или Esc, обрезание или горизонтальный скролл;
   - **minor** — выход за допуск по отступу, кеглю или цвету, текст не дословно.
4. Расхождения сгруппированы под будущие спеки исправлений (по экрану / подсистеме).
5. Скриншоты — локально в `.context/investigations/` (gitignored); в коммит идёт только `.md`.
6. URL подписки и ссылки серверов не попадают ни в логи, ни в скриншоты, ни в отчёт: печатается
   только длина или наличие; поля с ними маскируются перед снимком.
